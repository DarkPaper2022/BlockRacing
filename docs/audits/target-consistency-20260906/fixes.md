# 审计问题修复与累计进度复查

本页记录原审计基线 `b6efc02` 之后的 main 修复；原 `targets.csv` 审计表保留历史证据，不伪装成重新跑过全表审计。

## 已修改的规则

| 目标 | 当前实现 |
| --- | --- |
| 彩色羊毛 / 混凝土 64 个 | `item-total:64:<16 种颜色>`；允许混色，合计队伍在线背包与队伍箱当前数量，不累计转交历史。文案明确写“合计 64 个任意颜色”。 |
| 牛奶清除效果 | `actions:MILK_CLEANSE`；收到未取消、原因是 MILK 的实际效果移除事件才记录，不用普通喝奶记录代替。 |
| 织布机设计旗帜 | `actions:LOOM_CRAFT`；检查结果槽取出行为，再确认染料消耗且结果进入背包、光标或掉落。打开界面/选图案/满背包未取出不能完成。 |
| 炼药锅清洗物品 | `actions:CAULDRON_CLEAN`；检查盛水锅真实清洗皮革甲、旗帜或潜影盒的降水位事件。填水、装瓶、灭火和右键空锅不算。 |
| 堆肥桶填满并获得骨粉 | `actions:COMPOST_FILL,COMPOST_COLLECT`；队内有人成功使堆肥达到满层，且队内有人实际拾取玩家从成熟堆肥桶取出的骨粉。两步可分工，也不要求同一个桶；直接持有骨粉、右键空桶、漏斗操作不能代替。 |
| 唱片机播放唱片 | `actions:JUKEBOX_PLAY`；插入前为空，操作后确实正在播放且唱片匹配才记录。 |
| 挖钻石 / 绿宝石矿石 | 普通 `break:` 矿石目标接受相应深层变种，描述已注明。通用规则同时覆盖其余六种主世界矿石；明确指定 `DEEPSLATE_*` 的自定义任务仍严格匹配。 |

动作集合按队伍成员原始账本取并集，保存/恢复，不把历史 `use-block` 右键记录冒充真实操作。骨粉来源标记随当前对局 token 保存，掉落合并时传递，不能跨新对局使用；延后一 tick 的检查也核对对局 token，防止回调跨局。

## 累计进度数量检查

- 22 个指定 advancement key 在本机官方 26.2 客户端的进度定义中均存在且有 display。
- 新增测试通过真正的 `PlayerAdvancementDoneEvent` 监听入口记入 A 的 20 个、B 的 20 个且重合 10 个，队伍总数为 30。重复事件不会增加总数。
- 统计单位是完整 advancement ID，不是 criteria 数、配方数量或每人的完成数之和。排除 `recipes/`、无 display 的技术进度及非 minecraft 命名空间；有 display、但 `isHidden=true` 的真实隐藏挑战完成后仍计数。
- 登录/恢复导入只接受 `AdvancementProgress.isDone()` 的整个进度，多次导入不重复记入，部分 criteria 不跨人拼接；已记录离线成员保留贡献。
- **发现一个易误解的显示行为**：原菜单 `current = min(actual, required)`，实际 35 个在 30 目标上仍显示 30/30。本次增加未截断的有效进度去重总数；任务进度条仍封顶。
- **尚未改变的语义**：开局前已完成的进度也会导入，管理员撤销不会倒扣“曾完成”的账本。此行为可能使数值高于玩家只计算“本局新获得”的预期；未得到确认前不清空原版进度、不改这条规则。
- 当前测试没有复现重复累计或重复登录导致的数值错误。尚无用户侧偏多/偏少的具体样例，不能把显示修正宣称为已定位所有计数问题。

## 升级与验证边界

本次不覆盖运行服。安装时需在新局采用更新的插件、`Targets.csv` 和资源包；已有运行目录不会自动覆盖自定义 CSV。不要在未结束的对局中替换任务表：存档指纹不同会按既有机制备份为 incompatible 状态并拒绝混用规则。

已补充颜色总量、深层矿石、动作去重/恢复、真实成就事件与导入、无效织布机取出动作等回归测试。多人 Paper 26.2 实服仍需验证：织布机普通/Shift/快捷栏/丢弃取出、取消操作、炼药锅清洗、堆肥骨粉掉落合并/拾取/重启、唱片播放及各实际进度完成事件。上述实际操作涉及下一 tick 的状态检查，不能仅凭单元测试宣称已完成实服验收。

本次结果：54 项 Java 测试、9 项资源包测试、7 项导出测试及浏览器交互检查通过。最新审计 HTML 覆盖 158 个行为/组合目标，含 32 个候选轮播。构建产物暂存在约定部署目录的 `builds/target-consistency-fixes-20260906/`，没有替换运行服。
