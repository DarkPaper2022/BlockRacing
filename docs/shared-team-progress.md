# 队伍共享目标进度

状态：2026-09-06 已从 `feature/shared-team-progress` 合入 `main`；保留原开发分支。与暂停的 `feature/per-team-worlds` 无关，不创建额外世界。

## 共享规则

| 目标 | 队内判定 | 例子 / 边界 |
| --- | --- | --- |
| 造成 / 承受伤害、总击杀数、亡灵 / 节肢击杀次数 | 求和 | 49.6 + 50.4 伤害算 100，先合计再向下取整显示 |
| 不同敌对生物、繁殖类型、合成物品、观察类型、食物等 | 集合并集 | 两人都杀僵尸只算一种，重复击杀仍计入总击杀 |
| 完成 30 个进度 | 完整 advancement ID 并集 | A 有 20 个，B 有 20 个，其中重复 10 个：全队为 30 |
| 特定进度、击杀、驯服、食用、死亡原因、使用、钓鱼、村民等 | 任一队友已达成 | 一人完成即可满足全队；离线不撤销已记录事件 |
| 持有全部 / 任意 N 类物品 | 在线队友背包 + 全部队伍箱的当前物品快照 | 同种物品数量求和，类别去重；不累计“曾经持有”，传递同一张唱片不会增加类别数 |
| 特定附魔物品 | 任一背包或队伍箱中的单件物品完整满足 | 不把两把剑上的不同附魔拼成一把 |
| 同时穿戴、不同皮革颜色、效果数量、经验等级、位置、饥饿 | 同一队友完整满足；显示全队最佳个人进度 | 两人各穿半套铁甲不能算一整套；两人 20 级不能合为 40 级 |
| 连续穿戴 | 同一队友的连续时长，取全队最大值 | 两人各戴 3 分钟不能合为 6 分钟；主动断线会清除该人的连续计时 |

所有行为任务的菜单进度和自动完成判定共用一个聚合函数。菜单明确标注“队伍共享进度”或“队伍最佳个人进度 · 须同一人满足”；物品集合额外提示仅统计在线背包与队伍箱。点击底部页码可刷新。

普通单物品 `block` 任务仍采用原来的任一队友 / 队伍箱持有即可完成。任务池、积分、Bonus 和敌方抢先完成后移除目标的机制不变。

## 进度与存档边界

- 累计事件的原始记录仍按本局玩家名保存；查询时聚合，从不把合计结果再次写回个人记录。重复打开菜单、重复检查、重登或恢复不会把同一事件重复加算。
- 队伍成员在进行中的对局不能切换，红蓝两队的聚合名单相互独立；旁观者事件不进入账本。仍沿用项目的玩家名身份方案，不支持对局中管理员手改队伍名单或离线改名迁移。
- 已记录的伤害、唯一实体 / 食物、完整进度等保留离线成员贡献。离线背包不读入、不缓存，物品任务需要该成员上线或事先把物品放进队伍箱；否则缓存会把同一物品的搬运重复计算。
- 只统计 `minecraft` 命名空间、有展示信息、且不在 `recipes/` 下的原版进度。根进度有展示信息，照常计数；数据包计数器与配方解锁不算。某个进度的多个 criteria 仍须同一玩家先完成整个进度，不跨人拼接 criteria。
- 开局 / 重登 / 插件恢复时导入玩家已完成的有效进度，沿用旧版允许已有进度参与的语义；随后监听进度完成事件，不每 5 tick 遍历全部 advancement。记录是“已达成”而非当前未被管理员撤销的状态。
- `goals.COMPLETED_ADVANCEMENTS` 保存完整 ID 集合，`goals.sharing-policy: sum-union-v1` 标识策略。其余事件账本和原来的 format 2 存档兼容；旧存档没有 advancement 缓存的离线玩家需上线一次才能补录。
- 原自动保存周期为 5 秒，正常关闭、完成目标及断线也保存。强杀 / 断电仍可能丢失最后一次保存后的几秒，不承诺事务级实时落盘。恢复不会添加停机期间的连续穿戴时长。
- 被其他插件取消的伤害、繁殖、食用、采集等事件不计入；采用 MONITOR 阶段读取最终结果。
- 行为任务完成提示显示“队伍协作”，不把共享成果任意归给触发扫描的第一个玩家，也不追加到个人收集排行榜。普通物品任务仍保留原来的个人归属。

## 实现与验证

核心：`Goal.teamProgress`；界面：`Goal.getProgressLore`；结算：`Goal.findCompletionSource`。全队目标每轮只检查一次，不再每名队友重复扫描所有队友。

本地构建（不更改系统默认 Java）：

```sh

```

新增 `SharedTeamProgressTest` 覆盖：

- 小数伤害求和、重复成员去重、跨队隔离、重复查询不写回、YAML 保存恢复；

- 总击杀求和与实体 / 合成去重、全食物及布尔事件；

- 旁观者 / 非法伤害不计入，进行中的对局禁止换队；
- 完成判定与 UI 所用进度阈值一致。
