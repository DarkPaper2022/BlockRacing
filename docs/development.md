## 构建与部署

使用 JDK 25 或更新版本和 Maven，运行 Paper 26.2：

```sh
mvn clean verify
```

依赖已缓存时可用 `mvn -o clean verify`。构建产物为 `target/BlockRacing-26.2.1.jar`。`src/test` 覆盖抽样约束、Bonus 分类、菜单编号、CSV/Material/语言兼容性、行为进度 YAML 往返，以及上游的语言、聊天和命令逻辑；Maven 成功不能代替游戏内回归。

本机默认 Java 21 不足以构建新分支，可单次指定现有 JDK，不修改系统默认环境：

```sh
JAVA_HOME=/usr/lib/jvm/java-26-openjdk mvn clean verify
```

本机约定部署目录为 `~/Game/blockracing-draftout`。确认所需分支并停止服务器后，备份旧插件，再将新 JAR 复制到其 `plugins/` 目录。不要把 `main` 的构建误当成独立世界版本部署。服务端运行目录、JAR 和缓存均不提交到 Git。

插件仅在运行配置不存在时复制默认资源。部署代码后，如需更新任务或设置，应另行比较服务器与仓库的 `Targets.csv`、`config.yml`、`lang.yml`。

## 手工回归清单

以下是验证步骤，不是已通过的测试记录。使用专用测试服和可丢弃世界。

1. 启动插件，检查日志中的资源加载、Material/goal 解析和报错（尤其是需要服务端注册表的附魔目标，纯单元测试无法覆盖其解析）；打开准备菜单并测试选队、准备。
2. 用 `/sampleblocks 64` 检查普通任务数量、1 分上限、无重复目标。正式开局再核对 Bonus 数量和初始胜利门槛。
3. 分别完成一个物品任务、一个行为 goal、一个组合目标和一个 Bonus。核对进度、可用积分、菜单显示及对方任务移除。
4. 消耗积分进行定位与随机传送，确认胜利进度不变。检查箱子、队内传送和路径点。
5. 达到普通任务总分的一半，确认胜利判定与结束状态；Bonus 不能直接触发胜利。
6. 中英文玩家同时打开菜单、记分板；检查任务分页、编号、聊天隔离和 `/shout`。完成部分行为任务后正常停服重启，核对积分、任务与进度恢复。
7. 仅在可丢弃测试服验证 `/restartgame` 的全员确认、下一次启动的世界备份/重置；不要在正式世界上试验。
8. 若另行恢复独立世界分支开发，再额外检查双方世界种子、主世界/下界/末地隔离、往返传送门、死亡复活、断线重进和结束后清理。

独立世界版本启动时会清理 `world_red*`、`world_blue*` 的固定六个目录；不要在这些目录保存其他用途的世界。
