## 分支约定

`main` 是原 `local-3.5-patch` 的延续，保留积分制开发基线。`feature/per-team-worlds` 在此基础上增加队伍独立世界，暂不合并，以便单独验证这部分行为。基线修订应在功能分支同步。

`feat/lightkeeper-testing` 已删除：其唯一额外提交与独立世界分支中的 `/debug start`、忽略规则提交内容相同，没有独有代码。

`3.0` 和 `26.2` 保留上游快照。默认分支为 `main`，`origin` 指向本 fork，`upstream` 指向原作者仓库。

## 构建与部署

使用 JDK 21 和 Maven：

```sh
mvn clean verify
```

依赖已缓存时可用 `mvn -o clean verify`。构建产物为 `target/BlockRacing-3.5.jar`。当前没有 `src/test` 测试套件，Maven 成功不能代替游戏内回归。

本机约定部署目录为 `~/Game/blockracing-draftout`。确认所需分支并停止服务器后，备份旧插件，再将新 JAR 复制到其 `plugins/` 目录。不要把 `main` 的构建误当成独立世界版本部署。服务端运行目录、JAR 和缓存均不提交到 Git。

插件仅在运行配置不存在时复制默认资源。部署代码后，如需更新任务或设置，应另行比较服务器与仓库的 `Targets.csv`、`config.yml`、`lang.yml`。

## 手工回归清单

以下是验证步骤，不是已通过的测试记录。使用专用测试服和可丢弃世界。

1. 启动插件，检查日志中的资源加载、Material/goal 解析和报错；打开准备菜单并测试选队、准备。
2. 用 `/sampleblocks 64` 检查普通任务数量、1 分上限、无重复目标。正式开局再核对 Bonus 数量和初始胜利门槛。
3. 分别完成一个物品任务、一个行为 goal、一个组合目标和一个 Bonus。核对进度、可用积分、菜单显示及对方任务移除。
4. 消耗积分进行定位与随机传送，确认胜利进度不变。检查箱子、队内传送和路径点。
5. 达到普通任务总分的一半，确认胜利判定与结束状态。
6. 在独立世界分支额外检查双方世界种子、主世界/下界/末地隔离、往返传送门、死亡复活、断线重进和结束后清理。

独立世界版本启动时会清理 `world_red*`、`world_blue*` 的固定六个目录；不要在这些目录保存其他用途的世界。
